## Read with care

- **Not the reference machine.** D-05 names Windows 11 on a 4-core i3-12100-class CPU with 8 GB RAM and an SSD; this run is on the machine above. The verdict for the pilot is a run there (`pos-bench.exe --scale full`).
- The operating system's file cache is warm: the database was just written. A first scan after a reboot reads from disk.
- Times are the services the app's commands call, without the WebView and IPC (a few milliseconds more per command), and cold launch excludes the process and window start.

## What each measure times

- **Barcode lookup:** `lookup_code` for a random one of the barcodes (normalise, look up, load the variant).
- **Add item to visible cart:** a scan through `CartService::scan` on a cart of 1 to 20 lines, returning the priced cart.
- **Product search:** `search` for 20 results, cycling through typical queries.
- **Cash-sale local commit:** `complete_sale` for 3 lines paid in exact cash (one durable transaction, `synchronous=FULL`).
- **30-day sales report:** `sales_summary` for the last 30 days (figures per day and totals).
- **Sales list page:** `SalesService::list`, 50 rows: newest, a date range, a tender, a receipt number.
- **Cold launch (backend):** open the database (migration check, pragmas) and load the sign-in screen's staff list; the WebView's own start is not included.
