# ADR-006: Time

- **Status:** Proposed — needs acceptance by the tech lead and one other engineer (E00-T03)
- **Date:** 2026-11-05
- **Source:** [docs/backlog/03-decisions.md](../backlog/03-decisions.md), PRD §8–§14

## Context

The PRD (docs/PRD.md) fixes the product constraints this decision serves: offline-first local
checkout, atomic local transactions, at-least-once sync without duplicate effects, decimal-safe
money, and hardware independence. This ADR records the engineering choice the backlog assumes.

## Decision

- All instants are stored as an `INTEGER` count of **UTC epoch milliseconds**.
- Business-dated records (sales, returns, inventory documents, cash sessions) also store
  `business_date` (`YYYY-MM-DD`). It is computed at commit time from the business time zone
  (`chrono-tz`) and **never recomputed**.
- `Clock` is a port. Tests inject a fixed or stepping clock, and the timezone and day-boundary
  tests in PRD §16.3 use it.
- Device clock drift: the server records `received_at` and its own clock. Reports use the
  device's `business_date`. If a device clock differs from server time by more than 10
  minutes, the server raises a **clock-skew warning** on the sync status.

## Consequences

- Changing this after Stage 0 requires a new ADR that supersedes this one and an impact review of the tasks that cite it.
- Tasks citing this ADR in `docs/backlog/tasks/` must be re-checked if it is superseded.
